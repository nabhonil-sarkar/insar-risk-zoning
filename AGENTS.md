# Project session rules

Before project work, read the local `PROJECT_CONTEXT.md` completely if present
and inspect Git status. This handoff is private: never add it to Git, upload it,
or copy its contents into public issues, pull requests or documentation.
Preserve intentional modifications, additions and removals; do not reset or
discard them. Read README sections relevant to the task and only the latest
relevant CHANGELOG entries. Historical gates and checksums live in CHANGELOG;
retrieve the applicable entries before reusing an artifact or experiment.

Update documentation only when warranted:

- `PROJECT_CONTEXT.md`: live scope, evidence, decisions, blockers, next action
  or roadmap state changed.
- `README.md`: public scope/status, setup, architecture or supported usage changed.
- `CHANGELOG.md`: a material software, data or scientific milestone completed.

Do not update every file automatically or append unchanged session summaries.
Keep current facts in context and historical detail/checksums in changelog;
use links instead of repeating them. Date test results honestly.

Do not create another status, plan, roadmap, context, handoff or problem log.
`docs/InSAR_Subsidence_Risk_Zoning_Methodology.docx` is the sole methodology;
edit only for a major scientific method change or validated-result milestone.
Documentation cleanup alone does not require a methodology edit.
