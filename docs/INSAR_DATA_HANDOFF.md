# Matched LiCSBAS input handoff

The production pipeline expects one matched LiCSBAS stack generated by
`notebooks/LiCSBAS_Jakarta_vstd_rerun_v4.ipynb`.

Place these files in `data/raw/insar/`:

- `jakarta_vel_2020_2023.tif`
- `jakarta_vstd_2020_2023.tif`
- `jakarta_coh_avg_2020_2023.tif` (optional quality mask)
- `jakarta_n_unw_2020_2023.tif` (QA/provenance)

All supplied layers must come from the same inversion and have the same native
width, height, CRS, transform, period token, and footprint. The notebook also
creates `jakarta_licsbas_2020_2023_manifest.json` with checksums and processing
metadata; retain it beside the archived source data.

Before ingestion:

```powershell
py -3.14 scripts/validate_inputs.py --json data/output/input_validation.json
```

The validator fails on:

- multiple velocity or quality candidates;
- processed-product filenames in the raw directory;
- mismatched date tokens or native grids;
- multi-band InSAR layers;
- negative `vstd`/unwrap counts;
- coherence outside `[0, 1]`.

The May/July `jakarta_velocity_mmyr.tif` must be archived before the new stack
is placed in the raw directory. Do not mix it with a newly generated `vstd`.

Processed products (`calibrated`, `aligned`, `vertical`, `masked`,
`reproj`, or `nodata_masked`) are never valid raw inputs.
